# Cassandre plan: a brand kit from one prompt

Date: 2026-11-06. Branch: `cassandre` (after `ui-refresh`). Brief: the owner's request of
2026-11-06.

## Name

**Cassandre**, after A. M. Cassandre (1901–1968), the French poster artist and type designer of
Bifur and Peignot, whose work is a lesson in turning a brand into a system. It is used as a feature
name only. No artwork, typeface or likeness of his is used. Alternative if the owner prefers:
**Delaunay**, after Sonia Delaunay, for color.

## What it does

The user writes one prompt, for example "a calm budgeting app for students". Cassandre plans and
then builds a complete, original brand kit in the project, under `.moonfold/brand/`:

- a name;
- a logo and its variants;
- color with roles for light and dark;
- type with a hierarchy;
- spacing, radius, elevation and motion;
- voice and tone;
- ready-to-use exports and a brand book page.

It can collect design references from the web first, with the user choosing how. A review panel
then scores the kit and pushes it until the score stops improving.

It is not a new agent. It is a built-in skill that guides whichever agent the thread uses, plus a
small server service that does the parts that must be exact:

- validating the files;
- checking contrast;
- generating exports;
- rendering images.

## Principles

1. **Original output.** References inform principles (palette relationships, layout patterns,
   type pairings), described in our own words. Assets are never traced, copied or generated "in
   the style of" one named work.
2. **The user decides at each gate:** after the brief, the name, the direction and the final
   review. Nothing is applied to the project's own code unless asked.
3. **Exact where it matters.** Agents write the creative source (`tokens.json`, SVGs, Markdown).
   The service validates it and generates every export from it, so exports never drift.
4. **Licenses are tracked.** Fonts come only from OFL, Apache-2.0 or MIT families, and their
   license files are saved beside them. Every reference keeps its source and author.
5. **Works with every provider.** Any agent that can read a skill or a prompt profile and call
   MCP tools can run it. No step needs image generation: logos are SVG written as code.

## The folder

```
.moonfold/brand/
  brand.json              manifest: name, version, step status, sources, licenses
  brief.md                what the user asked for, audience, personality, constraints
  plan.md                 the steps for this kit, approved by the user
  name/
    candidates.md         10–20 names with meaning and rationale
    checks.json           domain (RDAP), GitHub, npm, package store lookups per candidate
    decision.md           the chosen name and why
  references/             not committed by default (see References)
    index.json            url, site, author, captured at, why it was kept
    shots/                small screenshots for private study
    analysis.md           patterns found, in our own words
  directions/
    a.md  b.md  c.md      two or three distinct directions
    board.html            one page comparing them; the user picks one
  tokens/
    tokens.json           source of truth, W3C Design Tokens (DTCG) format
  color/
    palette.md            scales, semantic roles, contrast matrix
  type/
    type.md               families, scale, hierarchy roles
  fonts/<family>/         .woff2 files and the family's license
  logo/
    logo.svg  symbol.svg  wordmark.svg  mono.svg  inverse.svg
    png/                  rendered sizes
    usage.md              clear space, minimum size, do and don't
  icons/
    app-icon.svg          plus rendered sizes and favicon set
  voice/
    voice.md              tone, word list, do and don't, sample copy
  templates/
    og-image.svg  social-avatar.svg  email-header.svg
  exports/                generated by the service, never edited by hand
    tokens.css  tailwind.css  tokens.scss  tokens.ts  tokens.json
  reviews/
    rubric.md  round-01.md …  scores.json
  guidelines/
    index.html            the brand book, self-contained
  LICENSES.md             fonts and any third-party material
  README.md               what is here and how to use it
```

`tokens.json` covers:

- color: primitive scales in OKLCH, plus roles such as background, foreground, primary, accent,
  muted, border, success, warning, danger and focus, for light and dark;
- typography: families, a modular scale, and the display / h1–h6 / body / small / caption /
  label / code roles, each with size, line height, weight and tracking;
- spacing, radius, border width, elevation, motion durations and easings, and icon stroke.

## How it runs

Each step updates `brand.json`, so a kit can be paused, resumed, handed off to another provider,
or re-run from any step.

1. **Brief.** Turn the prompt into `brief.md`. Ask only what changes the result: audience, three
   personality words, competitors to stand apart from, things to avoid, light or dark first, and
   where the brand will live (app, web, print). Questions use the provider's own question tool.
2. **Plan.** Write `plan.md`: steps, the reference mode, the review panel and a token budget. The
   user approves it. This uses plan mode where the provider has one.
3. **Name.** Skipped if the user has a name.
   - Generate candidates with meaning and pronunciation notes.
   - Check each with free, no-key lookups: domain availability by RDAP, GitHub organization, and
     npm.
   - Link to WIPO's Global Brand Database for a trademark search. Moonfold never says a name is
     legally clear.
   - The user picks one.
4. **References.** The user chooses a mode in the plan:
   - **Mine.** The user drops images or links. Nothing is fetched.
   - **Search with me** (default). Cassandre opens searches in Moonfold's browser pane, and the
     user keeps what they like through a "Keep for brand" action. That covers Pinterest and
     Dribbble.
   - **Search for me.** The agent browses on its own, but only sites whose terms allow automated
     access, plus the user's own competitor sites. Pinterest's terms forbid automated collection
     without written permission, so it stays in "search with me". Dribbble's terms still need
     checking and are treated the same until then. Agent browsing site rules
     (Allow / Ask / Block) apply as usual.
   - **Skip.**

   Kept references go into `references/index.json` with their source. The folder is added to
   `.gitignore`, because the screenshots belong to their authors. `analysis.md` records the
   patterns: palette relationships, layout grids, type pairings, density, and what to avoid
   because every competitor does it.

5. **Directions.** Two or three directions that differ in substance, each with a mini palette,
   type pairing, logo sketch and sample screen. They go on one `board.html`, shown in the thread as
   a visual reply. The user picks one, or mixes them.
6. **System.** Build the chosen direction:
   - `tokens.json`, then the palette, type and voice documents;
   - the SVG logo set, app icon and templates;
   - fonts with their licenses.

   The service then:
   - validates the kit;
   - checks the contrast of every declared foreground/background pair (AA: 4.5:1 for text, 3:1
     for large text and UI);
   - renders PNG sizes with the headless browser Moonfold already keeps for visual replies;
   - writes `exports/`.

7. **Review.** The hill climb, as in [ui-refresh.md](ui-refresh.md):
   - Screenshots of the brand book and the sample screens go to a panel of fresh reviewers, one
     per installed provider where possible (via `delegate_task`).
   - Each scores the rubric: originality, coherence, legibility, contrast, distinctiveness from
     the references, fit to the brief, and versatility. Each lists fixes.
   - Reviewers don't see the target score.
   - The agent fixes, re-renders and repeats until two rounds gain less than 0.2, the budget is
     spent, or 8 rounds pass.
   - Rounds go into `reviews/`. A run with one provider says so in the brand book.
8. **Hand over.**
   - The brand book `guidelines/index.html` opens in the file preview.
   - The thread ends with a summary and the folder.
   - "Apply to this project" (for example, wiring `exports/tailwind.css` into the app) is a
     separate, explicit request.

## Hit every surface

- **Providers.** Every adapter gets the skill. Claude and Codex load skills natively; the others
  get it as a prompt profile block, as with D-59. MCP tools work on every provider with MCP. A
  provider without MCP can still write the files, but loses validation and exports, and the plan
  says so.
- **Clients.** Web and desktop share the Brand view. Remote clients work, because files and
  rendering stay on the environment. On the phone the brand book renders in the web view, and
  "Keep for brand" is desktop and web only.
- **Agents and scheduled tasks** reach everything through the `brand` MCP tools.
- **Reverse states.** Delete a kit, re-run a step, roll back to the previous version (`brand.json`
  keeps versions), and remove a kept reference.
- **Handoff.** `brand.json` is part of the handoff brief, so a kit can continue in another agent
  after a usage limit.
- **Security.**
  - SVGs are checked for scripts, event handlers and external references before rendering.
  - References are fetched through agent browsing rules.
  - No credentials are ever entered.
  - Nothing leaves the machine except the lookups the user can see (RDAP, GitHub, npm).

## Order of work

The feature stays behind a build-time flag until steps 1–4 work against a real provider.

1. Contracts and `BrandKitService` with validation, contrast and exports, plus tests.
2. MCP toolkit and the built-in plugin source with the skill.
3. Brand view and entry points.
4. References: "Keep for brand" and the reference modes.
5. Review loop and the brand book template.
6. A live run with Claude Code end to end, and with Codex after 19 November. Write
   `docs/QA-CASSANDRE.md`. REA gate on any new dependency.
